## 一、为什么必须从第一天就记

官方模板要求填这些字段：

| 节 | 要填什么 |
|---|---|
| §1 工具与使用范围 | 工具名、**模型版本**、使用入口、硬件环境、使用目的、涉及模块 |
| §2 任务与成果 | 项目目标、**人工负责内容**、AI 参与范围、成果位置 |
| §3 AI 交互记录 | 提示词 + 回复摘录（可附原始会话导出） |
| §4 证据 | 对话截图 |
| §5 **AI 生成内容核验** | 独立一节 |
| §6 过程总结 | **人工判断的环节（哪些需要核实、修正或拒绝）** |

> **§5 和 §6 是重点**：评审要看的不是"你用了 AI"，而是"**你能不能判断 AI 哪里错**"。
> 这些记录**当天不写就丢了**，事后补只能编。

## 二、每条记录的固定格式

复制下面这段，填好存成 `ai-log/2026-11/MMDD_任务名.md`。

```markdown
### [日期] 任务名

- 工具 / 模型版本：
- 使用入口：网页 / IDE 插件 / API / 其他
- 使用目的：需求分析 / 代码生成 / 调试 / 解释学习 / 测试 / 文档
- 涉及模块：

**我的提示词：**

\`\`\`
（原样贴，不要润色）
\`\`\`

**AI 的关键回复（摘录）：**

\`\`\`
（只摘与任务直接相关的部分）
\`\`\`

**★ 我核实 / 修正 / 拒绝了什么（必填）：**

- 它说错了什么：
- 我怎么发现的：
- 我改成了什么：

**会话导出文件：** （文件名，或"未导出"）
```

## 三、一条反直觉的建议

**把 AI 说错的也留着。**

只记"AI 帮了我大忙"的记录，评委一看就是模板；
留一条"它编了一个不存在的接口，我查文档发现后改掉了"，可信度立刻不一样。

**评审要的是判断力，不是使用量。**
